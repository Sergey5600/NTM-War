## 2. Рецепты

Обозначения материалов — имена OreDictionary HBM (подходит любой предмет с этим именем).

| Результат | Ингредиенты | Где |
|---|---|---|
| 2× Сердечник БОПС (W) | 3× `ingotTungsten` по диагонали | верстак |
| 1× Сердечник БОПС (ОУ) | 3× `ingotUranium238` по диагонали | верстак |
| 2× Ведущее устройство | 3× `plateAluminum` (` A ` / `A A`) | верстак |
| 1× Метательный заряд 125 мм | 3× `dustAnySmokeless` (кордит/баллистит) + 2× бумага + 1× нить (бесформенный) | верстак |
| 3× Кумулятивная воронка | 3× `plateCopper` (`C C` / ` C `) | верстак |
| 2× Корпус снаряда 125 мм | 5× `plateSteel` (`P P` / `P P` / ` P `) | верстак |
| 1× Броневая плита | 8× `plateSteel` + 1× `blockSteel` в центре | верстак |
| 4× Элемент ДЗ | 1× броневая плита + 2× `ingotAnyHighexplosive` (ТНТ/TATB) + 2× `plateSteel` (` H ` / `PAP` / ` H `) | верстак |
| 1× Выстрел БОПС (W) | сердечник W (верх) + ведущее устройство (центр) + метательный заряд (низ) | **Ammo Press HBM** |
| 1× Выстрел БОПС (ОУ) | сердечник ОУ + ведущее устройство + метательный заряд | **Ammo Press HBM** |
| 1× Выстрел кумулятивный | воронка (верх-лево) + `ingotAnyHighexplosive` (верх) + корпус (центр) + метательный заряд (низ) | **Ammo Press HBM** |
| 1× Выстрел ОФС | `ingotAnyHighexplosive` (верх) + корпус (центр) + метательный заряд (низ) | **Ammo Press HBM** |

Итого 8 рецептов на верстаке и 4 в Ammo Press. При `shellRecipesInAmmoPress=false` или несовместимом API HBM
выстрелы крафтятся на верстаке из тех же ингредиентов (бесформенно): тогда 12 на верстаке и 0 в прессе.

**Баланс.** У HBM кумулятивная ракета РПГ: 1 `plateCopper` + 1 ТНТ + 1 большая гильза + 3 бездымного пороха
→ **2 ракеты**. Наш кумулятивный выстрел ≈ ⅓ медной пластины + 1 ТНТ + 2,5 стальной пластины +
3 пороха + бумага/нить, то есть примерно 2 ракеты: калибр 125 мм против РПГ, порядок стоимости тот же.
ОФС — кумулятив без воронки, самый дешёвый. БОПС (ОУ) = 3 слитка U-238 на сердечник против 1,5 слитка
вольфрама у БОПС (W), а U-238 в HBM требует обогащения урана.

## 3. Что взято из HBM

**Материалы (через OreDictionary):** `ingotTungsten`, `ingotUranium238`, `plateCopper`, `plateAluminum`,
`plateSteel`, `blockSteel`, `dustAnySmokeless` (кордит, баллистит), `ingotAnyHighexplosive` (ТНТ, TATB).

**API HBM (только в `compat/HbmCompat.java`):**

* `com.hbm.util.CompatExternal.registerRecipeRegisterListener(IRecipeRegisterListener)` и
  `api.hbm.recipe.IRecipeRegisterListener` — подписка на (пере)загрузку рецептов машин;
* `com.hbm.util.CompatRecipeRegistry.registerAmmoPress(ItemStack, AStack[])` — рецепты Ammo Press;
* `com.hbm.inventory.RecipesCommon.OreDictStack` / `ComparableStack` / `AStack` — ингредиенты;
* `com.hbm.inventory.recipes.AmmoPressRecipes` — только имя класса, по нему слушатель узнаёт загрузку рецептов пресса;
* `com.hbm.hazard.HazardSystem.register`, `HazardData`, `HazardRegistry.RADIATION`, `HazardRegistry.u238` — радиация.

**Машина HBM:** Ammo Press (`tile.machine_ammo_press`). Радиационный тултип и облучение игрока делает сам HBM.

**Сборка:** `com.hbm:HBM-NTM:1.0.27_X5863:dev` с `maven.ntmr.dev/releases`. AT HBM применяется через
`useDependencyAccessTransformers` в RFG, файл не копируется.

## 4. Отступления от ТЗ и почему

1. **Визуальная проверка — выборочная.** Сборка, сервер и клиент проверены (п.0), но в игре не переключался
   русский язык, не собирался выстрел в самом Ammo Press и не проверялись все 12 рецептов в NEI по одному.
   Это осталось в чек-листе ниже.
2. **Папка проекта** — корень репозитория `NTM-War`, а не `ntm-war`: облачная сессия работает в уже
   склонированном репозитории. Внутри это та же структура проекта.
3. **git push не делался** (правило ТЗ, к тому же репозиторий на GitHub публичный, а лицензия не выбрана).
   Коммиты и тег `0.1.0` есть только локально, репозиторий передан файлом `ntm-war-0.1.0.bundle`
   (`git clone ntm-war-0.1.0.bundle ntm-war`).
4. **HBM подключается с официального Maven HBM, а не с Curse/Modrinth Maven.** У HBM есть свой Maven
   с уже деобфусцированным `:dev`-jar (так описано в README HBM). Это надёжнее, чем деобфускация релиза.
   Вариант через CurseMaven + `rfg.deobf` оставлен комментарием в `dependencies.gradle`.
5. **NEI — форк GTNH 2.7.69** (рекомендация шаблона), а не классический chickenbones. NEI-хендлеры HBM
   используют `codechicken.lib.gui.GuiDraw`, который есть в CodeChickenCore форка GTNH.
6. **Spotless выключен** (`disableSpotless = true`). Форматирование не проверить без запуска Gradle, а
   несовпадение со стилем GTNH роняло бы `build`. Checkstyle (запрет wildcard-импортов) включён, код ему
   соответствует.
7. **Версия 0.1.0 задана git-тегом `0.1.0`**: так версионирует шаблон GTNH, отдельного свойства для этого нет.
   На последующих коммитах версия будет `0.1.0-<ветка>.<N>+<хеш>`, пока не поставлен новый тег.
8. **Дополнительные классы сверх перечисленных в ТЗ:** `item/ItemBase` (общая настройка предметов),
   `registry/MachineRecipe` (рецепт машины без классов HBM: описание в `ModRecipes`, перевод в формат HBM в
   `HbmCompat`), `registry/ModCreativeTab`, `compat/HbmMaterials` (имена OreDictionary без импортов HBM),
   `client/TooltipHelper`, `CommonProxy`/`client/ClientProxy`, `ModConfig`. В `NtmWar` только жизненный цикл.
9. **Настройка `shellRecipesInAmmoPress`** (по умолчанию `true`) и запасной рецепт выстрелов на верстаке.
   Причины: API HBM помечен `@Untested`, а при пользовательском `hbmRecipes/ammoPress.json` HBM не вызывает
   слушатели сторонних модов (мод пишет предупреждение в лог).
10. **Пункты 3, 4, 6 ТЗ — свои предметы**: подходящих аналогов в HBM нет (подробно в `HBM_NOTES.md`, раздел 6).
11. **Вольфрам — слиток, а не пластина**: обычной вольфрамовой пластины в HBM нет, только литая.
12. **Радиация:** сердечник ОУ 0.1 RAD/с, выстрел с ОУ 0.075 RAD/с (слиток U-238 — 0.25).
13. **Оболочка метательного заряда** — бумага и нить: сгораемая гильза, как у реальных 125-мм выстрелов.
14. **Броневая плита — 8 стальных пластин + стальной блок** на верстаке. Литые и сварные пластины HBM
    требуют литейки и сварочного аппарата; для заготовки под 0.2 это рано, но вариант хороший на будущее.
15. Предупреждения о пропущенных lang-ключах Minecraft 1.7.10 в лог не пишет. Поэтому ключи проверяет
    `tools/check_resources.py`, а мод при старте проверяет материалы HBM в OreDictionary.

## 6. Предложения на 0.2 (без реализации)

1. **Сущность снаряда** `EntityShell`: создаётся из `ShellSpec` при выстреле. Собственная баллистика: скорость,
   гравитация, упрощённое сопротивление воздуха для БОПС. Трассировка по блокам и сущностям на каждом тике
   с субшагами, чтобы снаряд на 1700 м/с не проскакивал сквозь блоки.
2. **Модель пробития в `ballistics/`** отдельно от сущности: `PenetrationModel` по `ShellType`.
   * БОПС: пробитие падает с дистанцией (потеря скорости), эффективная толщина = толщина / cos(угла),
     рикошет при угле больше ~70–75°, нормализация.
   * Кумулятив: пробитие не зависит от скорости, ДЗ вычитает большую долю.
   * ОФС: фугасное и осколочное действие через взрывы HBM (`ExplosionVNT`) с ограничением разрушения блоков.
3. **Броня плитами:** `ArmorPlate` = материал (RHA, композит, ДЗ) + толщина + нормаль. Техника описывается
   набором плит в своей системе координат (корпус, башня, борт, корма). Попадание → поиск плиты → угол встречи
   → сравнение с пробитием.
4. **Заброневое действие:** после пробития рассчитывать урон модулям и экипажу (двигатель, боеукладка,
   наводчик). Для начала можно просто снимать HP с сущности техники с коэффициентом по типу снаряда.
5. **Танк как сущность**: `EntityTank` с корпусом и башней (раздельный поворот), пушка заряжается
   `ItemShell` (берёт `ShellSpec`). Синхронизация — через пакеты FML SimpleNetworkWrapper.
   Рендер в `client/` (OBJ/Techne-модели).
6. **Интеграция с HBM:** цели турелей HBM (`CompatExternal.registerTurretTargetSimple`), радиационное
   загрязнение от попаданий ОУ, взрывы HBM для ОФС. Вариант: перенести крафт плит на литые/сварные пластины HBM.
7. **Инструменты баланса:** вынести `ShellSpecs` в JSON-конфиг с горячей перезагрузкой командой.
